# 실제 업체 연동 — 적대적 검토 및 후속 계획

## 요구사항과 범위

사용자가 제공한 업체 CSV를 실제 DB 및 업체관리 화면에 연결한다. 가져온 실업체는 연결된 조직의 ADMIN만 조회·수정하고 OPERATOR·VIEWER 및 다른 조직의 ADMIN은 접근할 수 없어야 한다. 원본 CSV와 한전 자격증명은 공개 산출물에 포함하지 않는다.

## 소스 검토와 수정

이번 검토는 구현 담당자의 직접 소스 검토와 실행 시험이다. 외부 독립 보안 감사로 표현하지 않는다.

| 발견 내용 | 수정 및 검증 |
| --- | --- |
| 역할 권한만으로는 같은 조직의 실업체를 OPERATOR가 볼 수 있음 | `admin_only`를 도입하고 목록·상세·수정·계측·한전·수집 작업의 서버 접근 경계에 적용. 직접 API 거부 및 교차 조직 테스트 |
| 기존 CSV 변환 명령이 클라이언트 목데이터 JSON을 생성 | 명시적 대상 DB·ADMIN·파일 해시를 요구하는 비공개 트랜잭션 importer로 교체. 이전 무인자 실행은 실패하며 fixture 무변경 |
| 키 분실 후 새 CSV 반영 시 새로운 키와 기존 암호문이 섞일 수 있음 | 기존 암호문이 있으면 키 생성 금지, 기존 암호문 전체 복호화 확인 후 반영. 누락·다른 키 거부 및 정상 키 복원 후 재시도 테스트 |
| 새 자격증명 테이블이 비식별 사본에 잔존할 수 있음 | 자격증명·가져오기 이력·원본 해시 제거, secure_delete 적용. DB 쿼리와 파일 바이트 잔존 검증, 원본 무변경 |
| 기존 비식별 명령이 출력 경로 중복을 거부한 뒤 기존 파일을 삭제할 수 있음 | 이번 실행이 생성한 사본만 실패 정리 대상으로 제한. 기존 DB·메타데이터 보존 회귀 테스트 |
| 서버 파일 추적에 원본 CSV·키·DB가 포함될 수 있음 | 키 파일 접근의 Turbopack 추적 제외, `.nft.json` 공개 검사 게이트 추가. 기본·사용자 지정 키와 경로 별칭 거부 테스트 |
| 좌표 입력란의 긴 라벨로 기존 편집창 폭이 증가 | 라벨과 입력 안내를 나눠 기존 2열 폼 폭 유지. 기존 브라우저 시나리오로 확인 |

## 실제 로컬 데이터 확인

- 기존 업체 1,654건 갱신, 신규 중복 생성 0건.
- 암호화한 비어 있지 않은 한전 비밀번호 1,550건. 화면/API 원문 반환 없음.
- 원본 대조에서 업무 필드·복호화 값 불일치 0건, 외래 키 위반 0건.
- 실제 DB 브라우저 검사: ADMIN 1,654건, OPERATOR/VIEWER 각 0건. 관리자 저장·재조회, 비관리자 직접 API 403, 익명 401.
- 원본 범위를 벗어난 좌표 1건은 값 보존 및 관리자 확인 안내.

건수 외 실제 고객 값·원본 경로·암호화 키는 이 문서와 Git에 포함하지 않는다. 비공개 로컬 보고서가 실제 반영 및 백업 증거를 보관한다.

## 검증 상태

- 최종 전체 단위/API 시험: 27개 파일, 216개 통과.
- typecheck 및 최종 프로덕션 빌드 통과. E2E는 분리된 합성 DB와 `.next-e2e`를 사용했다.
- 브라우저 전체 초회 82/83 통과. 좌표 라벨 폭 수정 후 영향을 받는 업체관리·모바일 18개 모두 통과. 기존 실패 시나리오를 삭제하거나 폭 허용치를 완화하지 않았다.
- 공개 번들 및 최종 배포 추적 58개 검사 통과. 실제 키 경로를 환경변수로 지정한 검사도 통과.
- 약 1.15GB(1,150,169,088바이트) 반영 후 로컬 DB 백업을 다시 열어 무결성 `ok`, 외래 키 위반 0, ADMIN 1,654건/OPERATOR·VIEWER 0건 및 암호문 1,550건 복호화를 확인했다. 외부 운영 DB 복구 검증을 대신하지 않는다.
- 초회 단위 시험의 기존 5초 마이그레이션 시험 시간 초과는 빌드 동시 실행 종료 후 해소됐다. 새 추적 검사에서 발견한 macOS 경로 별칭 문제는 정규화로 수정하고 전체 재시험했다.
- 브라우저 보고서 생성 후 ESLint가 Playwright의 생성된 번들을 읽는 문제는 보고서·실행 결과 폴더를 제외해 수정했다. 제품 소스와 `e2e/`는 계속 검사한다. 별도 프로젝트가 복사된 로컬 작업 폴더 3개만 CLI에서 추가 제외했다.

## 다음 작업과 완료 경계

1. 이번 변경의 최종 테스트·프로덕션 빌드·브라우저 검사 후 통합 브랜치에 커밋·푸시하고 해당 커밋 CI를 확인한다.
2. migration 013 및 암호화 자격증명을 포함한 반영 후 DB를 일관 백업하고, 백업 DB와 보관 키 조합의 읽기·권한·복호화를 검증한다.
3. 실제 서비스 URL과 배포 서버가 확인되면 배포 SHA·운영 migration 011/013·서버 스케줄러·webhook 설정을 읽기 전용으로 감사한다. 로컬 증거로 외부 배포를 완료 처리하지 않는다.
4. 계측 원본 대조에는 별도의 승인된 시계열 원본과 대상 기간·단위·계측점이 필요하다. 이번 업체 마스터 CSV를 계측 원본으로 대체하지 않는다.
5. 승인된 알림 수신처의 실제 수신 확인과 7일 관찰은 해당 환경과 담당자가 정해진 뒤 수행한다. 코드·합성 테스트 완료를 실운영 관찰로 대체하지 않는다.

기존 미완료 운영 항목은 [잔여 운영 준비](../ops/remaining-blockers-status.md)를 따른다. 새로운 실업체 정보 연동은 기존 관측 데이터·운영 게이트의 완료 표시를 바꾸지 않는다.

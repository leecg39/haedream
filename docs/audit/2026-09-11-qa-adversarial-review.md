# QA · 적대적 검토 및 수정

기준 브랜치: `feat/fit-clone`, 시작 커밋: `f9d0870`.

요청 범위는 현재 앱의 QA, 적대적 검토, 발견 사항 수정 및 커밋·푸시다. `code-review`의 요구사항 검토와 코드 품질 검토를 적용했다. Gemini 도구가 제공되지 않아 교차 모델 검토는 수행하지 않았으며, 아래는 직접 소스 검토와 실행 시험 결과다.

## 발견 사항과 수정

| 심각도 | 재현한 문제 | 수정 및 근거 |
| --- | --- | --- |
| Important | 서버 배포 추적 검사에서 심볼릭 링크인 `data`와 외부 `DATABASE_PATH`의 DB·보조 파일을 허용 | 원래 추적 경로와 실제 경로를 함께 검사하고, 설정된 DB·WAL·SHM·journal을 확장자와 무관하게 차단. 최초 5개 실패 재현 후 수정, DB 파일 링크 사례까지 총 6개 회귀 테스트 추가 |
| Important | 워커가 ADMIN 요청도 OPERATOR로 고정하여 관리자 전용 업체 수집이 실패 | 요청자의 활성 계정·조직·현재 역할을 DB에서 읽고 기존 업체·수집 권한 검사 적용. 합성 암호화 자격증명이 어댑터에 전달되고 작업이 SUCCEEDED가 되는 시험 추가 |
| Important | 대기 작업의 요청자 비활성화·역할 강등을 실행 시 확인하지 않으며, 접근 거부도 재시도 | 실행 직전 권한 확인. 비활성 계정·VIEWER 강등은 일반 업체에서도 호출 차단, OPERATOR 강등은 관리자 전용 업체 차단, 수집 권한 회수 차단을 검증. 모두 외부 호출 없이 1회 시도 후 FAILED |
| Minor | 기본 린트가 약 15GB의 로컬 워크트리 사본·운영 산출물을 탐색 | 해당 3개 로컬 폴더만 ESLint 제외. 제품 소스·테스트는 계속 검사 |

## 요구사항 검토

- 실업체의 ADMIN 제한과 조직 경계, 비권한 PII 마스킹, 직접 API 우회 거부를 기존 테스트 및 서버 접근 코드와 대조했다.
- CSV 가져오기의 트랜잭션 원자성, 키 손실·교체 거부, 재가져오기 멱등성을 기존 테스트와 대조했다.
- 신규 워커 시험은 외부 한전 호출 대신 합성 어댑터를 사용하며, 역할 고정에 따른 실제 실패를 수정 전 재현했다.
- 코드 변경은 배포 검사·수집 실행 권한·린트 범위에 한정한다. 기존 사용자 변경인 `.commandcode/taste/workflow/taste.md`와 비공개 로컬 폴더는 커밋에 포함하지 않는다.

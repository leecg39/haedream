# 실제 업체 CSV 연동과 관리자 권한

2026-09-07 구현. `firm-details.csv`를 정적 목데이터로 변환하는 기존 스크립트를 폐기하고, 실제 `firms` DB와 관리자용 목록·상세·수정 화면에 연결했다.

## 권한

- CSV로 가져온 업체와 ADMIN이 새로 등록한 업체는 `firms.admin_only=1`이다.
- 해당 조직에 연결된 활성 ADMIN만 조회·수정할 수 있다. 다른 조직의 ADMIN은 접근할 수 없다.
- OPERATOR·VIEWER는 같은 조직이어도 업체 목록/선택 메뉴에 해당 행이 나오지 않으며 상세·수정·계측·한전 상세·수집 작업 조회가 거부된다.
- 권한은 데이터 조회·수정 직전과 API에서 검사한다. UI 숨김에 의존하지 않는다.
- 가져온 업체에는 고객정보 열람을 허용하지만 새 수집 실행 권한을 자동 부여하지 않는다. 기존의 별도 수집 권한이 있는 경우에는 그대로 유지하며 ADMIN 제한이 추가 적용된다.

## 가져오기

먼저 SQLite backup API로 일관된 사본을 저장하고 사본에서 migration 013과 아래 작업을 검증한다. 원본 CSV·DB는 0600 권한의 비공개 파일이어야 한다. 원본·암호화 키·DB·백업은 Git/공개 파일에 넣지 않는다.

```sh
npm run db:import:firms -- \
  --csv /private/firm-details.csv \
  --db /private/app.db \
  --tenant ORG_ID \
  --actor ADMIN_USER_ID \
  --expected-sha256 CSV_SHA256
```

기본은 dry-run이다. 실제 반영은 같은 명령에 `--apply`를 추가한다. `FIRM_CREDENTIAL_KEY_PATH`는 별도 비공개 키 파일 경로를 사용한다. 최초 반영 때 키를 생성하며 기존 키는 덮어쓰지 않는다. 변경 로그와 실행 결과에는 원문 대신 출처 해시와 건수만 기록한다.

전체 CSV를 검증한 뒤 업체·권한 연결·암호화 자격증명·실행 이력을 한 트랜잭션으로 저장한다. 중간 실패 시 모두 취소한다. 같은 조직에서 같은 파일을 다시 실행하면 재적용하지 않으므로 관리자가 화면에서 수정한 값이 오래된 CSV로 덮이지 않는다. 다른 조직과 이미 연결된 업체 ID가 있으면 자동으로 소유권을 바꾸지 않고 거부한다.

## 데이터와 수정

- 고객번호는 문자열로 보관하여 앞자리 0을 보존한다.
- 업체명·연락처·주소·계약 정보·운영 설정·지도 좌표를 목록/상세/수정에 연결한다. 목록에는 연락처·주소·지도 좌표를 포함하지 않는다.
- 일반적인 POINT 좌표는 경도/위도 문자열로 보존한다. 원본 범위를 벗어난 좌표는 임의로 바꾸지 않고 상세 폼에서 확인 필요 안내를 표시한다.
- 한전 비밀번호는 AES-256-GCM으로 암호화하며 업체 ID를 인증 데이터에 묶는다. 조회 API·폼에 원문을 보내지 않는다. 비어 있는 비밀번호 입력은 기존 비밀정보를 삭제하지 않는다.
- 관리자 수정은 버전 충돌 검사(409)와 감사 기록을 거쳐 저장한다. 저장 성공 후 목록을 다시 조회한다.

암호화 키가 없으면 저장된 한전 자격증명을 복호화할 수 없으므로 DB와 함께 안전하게 백업하되 접근을 제한한다. 기존 `KEPCO_PASSWORDS_PATH` 로더는 암호화 저장값이 없는 업체의 이전 서버 설정과 호환된다.

암호문이 이미 존재하면 재가져오기에서 키를 새로 만들지 않는다. 기존 암호문 전체가 설정된 키로 복호화되는지 먼저 확인하고, 키 분실·교체·암호문 손상은 DB 변경 전에 거부한다. 정상 DB와 일치하는 키를 복원한 뒤 재시도한다.

`db:deid-snapshot`은 사본에서 `firm_credentials`, `firm_import_runs`, 업체의 원본 해시를 지우고 SQLite `secure_delete`를 켜 삭제한 암호문이 여유 페이지에 남지 않게 한다. 원본 DB와 키는 그대로 유지한다. 비식별 사본은 원래 자격증명 복구용 백업이 아니다.

이 CSV는 업체 마스터와 설정 값이다. 이를 가져온 것만으로 새로운 시계열 계측·자동 수집·절감 실적이 검증되는 것은 아니다. 한전/RTU로 실제 요청을 발송하는 작업은 이번 가져오기에서 실행하지 않는다.

## 검증

합성 fixture로 dry-run 무변경, ADMIN 성공, OPERATOR/VIEWER 및 다른 조직 ADMIN 거부, 직접 API 우회 거부, 암호화/업체 간 ciphertext 교체 거부, 중복 입력·잘못된 입력·DB 실패의 원자성, 재실행 시 수정값 유지, DB 재개방 후 저장 유지, 기존 정적 JSON 미생성을 테스트한다.

실제 적용 건수·원본 대조·브라우저 검증·백업 위치는 로컬 비공개 결과 폴더의 보고서에 기록한다. 원문 고객정보와 자격증명은 이 문서에 포함하지 않는다.

`npm run check:public-data`는 공개 번들 검사와 서버 배포 `.nft.json` 추적 검사를 함께 실행한다. 원본 CSV·로컬 DB·기본 키·환경변수로 지정한 키가 추적되면 실패한다. 별도 빌드 폴더는 `NEXT_DIST_DIR`로 지정한다. 빌드 추적이 없는 상태를 통과로 간주하지 않는다.

외부 볼륨의 DB는 검사 실행 시에도 운영 대상과 동일한 `DATABASE_PATH`를 지정한다. 검사기는 해당 DB와 WAL·SHM·journal 파일을 확장자와 관계없이 차단하며, `data` 디렉터리와 DB 파일의 심볼릭 링크도 검사한다.

수집 워커는 요청자의 현재 활성 상태·조직·역할을 DB에서 다시 조회한 뒤 업체 접근 및 수집 권한을 검사한다. 관리자 전용 업체는 요청자가 실행 시점에도 ADMIN이어야 한다. 계정 비활성화나 권한 회수로 거부된 작업은 외부 호출 없이 FAILED로 종료하며 자동 재시도하지 않는다.
